Status legend:

- **RESOLVED**: binding.
- **ASSUMED**: a default that stays in effect until the client answers. Build it behind configuration so it can change without a rewrite.
- **OPEN**: needs an answer before the listed milestone. Until then, use the stated default and keep it configurable.

Changing a RESOLVED row needs the human's approval. When you add a row, put the milestone that created it in the Notes column.

## Assumptions log (append during sessions)

Format: `- <date> · <milestone> · D-0xx · <assumption> · <why this default> · <how to change it>`

- 2026-09-20 · kickoff · D-034 · Each org carries a `brand` jsonb; neutral placeholder logo and a single shared accent hue until the client supplies real assets · Five brands were described as separate units but the architecture had no branding anywhere, so every invoice and every console would have looked identical · Replace the placeholder values per org; no code change, the values are data.
- 2026-09-20 · kickoff · D-035 · Branded login resolves the org from the route or hostname and preselects it · The client asked for a separate login per sister org; one identity with memberships is the correct model, so we meet the intent at the surface instead of forking accounts · Drop the org-resolution middleware and always show the switcher.
- 2026-09-20 · kickoff · D-037 · A settlement dated in a closed period posts to the earliest open period, keeping its own date as a reference · Courier settlement files routinely arrive after month-end close; the alternative is reopening a closed period every month · Change the resolver in the settlement posting rule; the reference field already records the true date.
- 2026-09-20 · M00 · D-039 · TypeScript pinned to 6.0.3 rather than the latest 7.0.2 · TypeScript 7 removed the classic compiler API, so type-aware lint rules — the ones that catch an un-awaited ledger post or a string/number mix-up on money — would stop working · Bump the catalog entry in pnpm-workspace.yaml once typescript-eslint supports 7.x.
- 2026-09-20 · M00 · D-040 · Packages compile to dist via project references; tests alias to source · The server needs emitDecoratorMetadata, which esbuild cannot emit, so a real tsc build is unavoidable, and aliasing tests to source keeps `pnpm test` independent of build order · Switch to a `development` export condition if dev startup gets slow.
- 2026-09-21 · M01 · D-042 · erp_owner is created NOSUPERUSER and the container superuser is a separate role · A superuser bypasses FORCE ROW LEVEL SECURITY, so with erp_owner as superuser every tenant policy was a no-op for the role that owns the tables — verified live before designing around it · Change the compose POSTGRES_USER and re-run db:bootstrap; the assertion in bootstrap.ts fails loudly if a role regains the attribute.
- 2026-09-21 · M01 · D-043 · The isolation policy wraps current_setting in nullif · A transaction-local set_config reverts to the empty string rather than unset, so the bare form throws on every reused pooled connection instead of returning zero rows · Emit a different expression from tenantTableSql() and add a migration; the policy is generated in one place precisely so this is a one-line change.
- 2026-09-21 · M01 · D-045 · Bangladesh geography is vendored rather than fetched, from a dataset compiled off the official gov.bd portals · A seed must not depend on a network, and inventing ~500 place names for a delivery system would produce mis-routed parcels and a zone table nobody trusts · Replace data/bd-geo.json and re-run the seed; ids come from the source so a reload is idempotent.
- 2026-09-21 · M01 · D-047 · Foreign keys between tenant tables carry org_id on both sides · PostgreSQL bypasses row security for referential-integrity checks, so a plain reference lets one org point at another's row — corrupting integrity, blocking that org from deleting its own row, and leaking an existence oracle · Drop the composite constraint and go back to a single-column reference, which the guard test will then fail.
- 2026-09-21 · M01 · D-048 · The tenancy guard is opt-out and compares the policy expression · An allowlist would have left every future module schema unguarded, silently, and counting policies would have let `using (true)` pass · Add a schema to GLOBAL_SCHEMAS or a table to GLOBAL_TABLES, which is then a visible decision rather than an omission.
- 2026-09-21 · M01 · D-049 · erp_analytics holds no read grant on any tenant table yet · A blanket cross-org SELECT would be a standing hole for the years before anything needs it; opting in per table keeps the blast radius equal to what analytics actually reads · Pass analyticsReadsAllOrgs to tenantTableSql in the migration that adds the rollup table.
