# M11: Order desk UI, buyer list, public order intake

Phase 1 · Effort XHIGH · Depends on: M10 · Architecture §9, §19, §23, §24

> Written on 2026-09-30, after the build. M11 was built on 2026-09-29 without a
> plan file. This records the plan as executed.

## Scope

An agent takes an order from a Facebook or WhatsApp chat in under 30 seconds
without touching the mouse, and a landing page can post an order safely.

## Out of scope

- The fraud score itself. The desk has a badge slot that M13 fills.
- Courier screens (M12, M15).
- Promo codes and buyer profiles (M16).
- The landing page builder that will call the public API (M29).

## Data model

Schema `intake`, migrations 0062 to 0064.

- `site_keys`: a key id and a SHA-256 fingerprint of the derived secret. The
  secret is never stored (D-136).
- `submissions`: the idempotency record for public orders.
- 0064 adds the indexes the order list filters and the queue need.

## Domain and server logic

- `apps/console/src/routes/orders/desk-logic.ts`: pure desk arithmetic and
  keyboard rules, unit tested in `orders-ui.test.ts`.
- `modules/intake/signature.ts`: HMAC over `timestamp.idempotencyKey.rawBody`
  with a 300 second window (D-137).
- `modules/intake/turnstile.ts`: Cloudflare siteverify.
- `modules/orders/timeline.ts`: status history merged with audit entries.
- `modules/orders/export/tabular.ts`: CSV and XLSX writers for the buyer list.

## API, events and screens

- Public: `POST /public/v1/orders`. Signed, Turnstile checked, rate limited,
  idempotent. It is exempt from the CSRF double-submit because it carries no
  cookie authority (D-133).
- Staff: `/v1/intake/site-keys` (list, issue, revoke), `/v1/buyers` and
  `/v1/buyers/export`, and on orders: `bulk-confirm`, `duplicates`, `agents`,
  `documents`.
- Realtime: the queue and lists listen to `order.created`, `order.assigned`,
  `order.claimed` and `order.status_changed` through the outbox.
- Console: `/orders` (list with filters), `/orders/new` (the desk),
  `/orders/queue`, `/orders/buyers`, `/orders/$orderId` (detail with timeline).
- `docs/public-api.md` is the integration guide for landing-page developers.

## Decisions

D-136 to D-141 and D-148 to D-151. The ones that protect money or data: a public
order cannot set a price, discount, charge, advance or assignee (D-138), unsafe
intake settings refuse to boot in production (D-139), and the buyer list and its
export both need `export BuyerExport` and are audited (D-148).

## Risks that mattered

- **The outbox dispatcher had never delivered an event.** Check 4 exposed it:
  the dispatcher claimed rows with no org context against a FORCE RLS table and
  saw none. Fixed in the platform layer (D-131, D-132), with migration 0072.
- **The public endpoint answered 403 to every real caller.** The CSRF check
  applied to a route no browser session calls. Fixed by D-133.
- **The API had no jobs runtime**, so any request that queued work threw
  (D-134).
- **A page of phone numbers is an export by another name**, so the list itself
  is gated like the export.
