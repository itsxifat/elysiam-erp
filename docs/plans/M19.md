Phase 3 · Effort MAX · Depends on: M08 · Gate: G7 · Architecture §7, §12

> plan file. This records the plan as executed.

## Scope

Staff records, attendance, salary structures and a payroll run that goes draft,
approve, post, pay. Salary and loan money reach the ledger through posting rules
like every other movement.

## Out of scope

- Targets, bonus rules and productivity (M20). A payroll run accepts bonus
  amounts as inputs and does not compute them.
- Biometric device integration. Attendance is manual entry or CSV import.
- Interest on staff loans (D-188).

## Data model

Schema `hr`, migrations 0053 to 0057.

- `employees`: sensitive fields encrypted with `HR_FIELD_KEY`.
- `work_calendars`, `calendar_holidays`: created on demand, Friday weekend by
  default (D-187).
- `salary_structures`, `salary_components` (D-029).
- `attendance_imports`, `attendance_days`.
- `employee_loans`, `loan_instalments`.
- `payroll_runs`, `payroll_inputs`, `payroll_lines`, `payroll_line_components`,
  `payroll_loan_deductions`.
- One live run per org per month, by a partial unique index (D-191).
- 0056 links a run to its approval request.

## Domain functions and what tests them

In `packages/domain/src/payroll`, tested in `payroll.test.ts`:

- `proration.ts`, `attendance.ts`: working days and the absence deduction.
- `loans.ts`: schedules and how deductions apply.
- `payroll.ts`: `computePayrollLine`, and the worked scenario for check 1.
- `csv.ts`: reviewing an attendance import before it is accepted.

Posting rules: `payroll-posted.ts` and `employee-loan.ts`. A property test
proves the payroll journal balances for random runs.

## API and screens

- 30 routes under `/v1/hr`: employees, salary, calendars, attendance and its
  imports, loans, payroll runs with inputs, preview, submit, pay, cancel, and
  payslips as PDF.
- A payslip is rendered on demand and never stored (D-189).
- Console: `/people`, `/people/attendance`, `/payroll`, `/payroll/loans`,
  `/payroll/runs/$runId`.

## Decisions

D-029 and D-186 to D-192. The ones that change money: an unrecorded working day
counts as present (D-186), a run under the org's threshold posts in the same
request (D-190), and salary and loans are paid out of a ledger wallet account
(D-192).

## Risks that mattered

Three critical findings from the ledger audit, all fixed with tests.

- **A payroll run under the approval threshold could never post.**
- **A run could be posted twice** by a retried request. The journal key and the
  run's status transition now refuse it.
- **Encrypted fields readable in a raw query.** Check 3 reads the table as the
  owner role and asserts ciphertext.

One risk is open and is a human decision: **one HR user can disburse a staff
loan they typed, with no second person.** §6 names no approval for staff loans
(D-188).
