# M00: Repo bootstrap and toolchain

Branch: `m00-repo-bootstrap` · Effort XHIGH · Architecture §3, §4, §24, §27, §28 · Gate G0 (partially unmet, see Risks)

## Scope in my own words

Build the empty house every later milestone moves into. Nothing in M00 does business work; everything in M00 decides how business work gets checked. The deliverable is one command — `pnpm verify` — that a later session can trust as the only gate between a change and `main`.

Three things make this milestone worth an XHIGH session rather than a quick scaffold:

1. **`pnpm verify` has to be strict on day one.** Loosening a lint rule in M17 because it was never enforced is how codebases rot. Strict TypeScript, type-aware lint, format check, and the two custom UI rules all land now, on an empty repo, where fixing violations costs nothing.
2. **The design token foundation (D-033) goes in before any component exists.** M05 builds the UI kit; if the tokens arrive with it, the first screens get written against hard-coded colours and the "premium" requirement quietly becomes a repaint job later. Tokens first means every component that has ever existed in this repo was written against them.
3. **The measurement harness goes in before anything needs measuring.** M06, M13, M22 and M29 all assert latency thresholds. If each invents its own method those numbers aren't comparable across sessions. One `scripts/bench.mjs`, one method.

### Explicitly out of scope
- Any domain table, migration, or Drizzle schema. `packages/db` is a compiling skeleton with a migrations folder and nothing in it.
- Authentication, Better Auth, sessions.
- Any UI component. `packages/ui` ships tokens, the Tailwind preset and fonts — no React in it yet.
- Chart/dataviz tokens. M24 picks those with the `dataviz` skill; placeholder chart colours now would get copied everywhere before anyone validated them. Logged as a follow-up.
- Chatwoot in the compose file (Phase 5).

### The TypeScript decision (matters, and contradicts "use the latest stable")

The milestone says to pin the latest stable release. The latest stable TypeScript is **7.0.2**, and I am deliberately **not** using it.

TypeScript 7 is the native port. I verified against the published package: `typescript@7.0.2` exports only `./unstable/*` entry points, and `require('typescript').createProgram`, `.SyntaxKind` and `.sys` are all `undefined`. The classic JS compiler API is gone.

`typescript-eslint@8.70.0` declares `typescript: ">=4.8.4 <6.1.0"` and needs that classic API for type-aware linting. On TS 7 we would lose exactly the rules that matter most here: `no-floating-promises` (an un-awaited `ledger.post()` inside a transaction), `no-misused-promises`, `restrict-plus-operands` (string/number confusion on money), `require-await`. Those are correctness rules for a system that moves real taka.

I verified **TypeScript 6.0.3** is published as a non-prerelease, is not deprecated, retains the full classic API (`createProgram`, `SyntaxKind`, `sys` all present), and sits inside typescript-eslint's supported range. I also verified 6.0.3 emits decorator metadata correctly, which NestJS DI depends on.

So: **TypeScript 6.0.3** — the newest stable TypeScript that keeps the safety net. New decision row **D-039**, with the migration trigger written down: move to 7.x when typescript-eslint ships support.

## Repo layout produced

```
apps/     server (api+worker), console, portal, pos, sites, extension
packages/ config, ui, i18n, contracts, domain, db, api-client, integrations, landing-blocks
infra/    docker-compose.dev.yml
scripts/  check-migrations.mjs, bench.mjs, fetch-fonts.mjs
.github/  workflows/ci.yml
```

**Package linking:** compiled packages with TypeScript project references. Each package emits `dist/` and its `exports` point there; `turbo build` gets real caching and `tsc -b` gives one authoritative typecheck across the graph. The alternative — source-only packages — is faster in dev but leaves the server needing a bundler that can emit decorator metadata, which esbuild cannot. `turbo dev` declares `dependsOn: ["^build"]` so package builds land before app dev servers start.

| Invariant | Test |

## Design tokens (D-033, architecture §24)

`packages/ui/src/styles/tokens.css` defines, for light and `.dark`:

- **Surfaces:** `background`, `foreground`, `card(-foreground)`, `popover(-foreground)`, `muted(-foreground)`, `accent(-foreground)`, `secondary(-foreground)`
- **Brand:** `primary(-foreground)`
- **Status:** `destructive`, `success`, `warning`, `info`, each with `-foreground` and a `-subtle` fill plus `-subtle-foreground`
- **Lines:** `border`, `input`, `ring`
- **Non-colour:** `--radius` (8 px) and derived steps, the 4 px spacing base, `--row-height: 2.25rem` (36 px), `--font-sans` / `--font-bangla` / `--font-mono`, shadows for floating layers only, `--duration-fast|base|slow` (120/160/200 ms) and `--ease-out`

Neutrals are cool greys (hue ≈ 264, chroma ≤ 0.01). Backgrounds are never pure black in dark mode — borders disappear against `#000` and it bleeds on OLED.

**Per-org accent derivation (D-034)** is the mechanic that makes five brands cost one design system. Tokens declare `--brand-h` and `--brand-c`; primary, its hover and active states, and the focus ring are all `oklch()` expressions over those two values, so M05 sets two custom properties from `org.organizations.brand` and every derived shade follows with its contrast intact.

**Fonts.** `@font-face` for Inter (Latin, numerals) and Hind Siliguri (Bangla), self-hosted woff2, `font-display: swap`. `scripts/fetch-fonts.mjs` downloads them from the official sources, reads each font's `unitsPerEm` and OS/2 `sxHeight`, and computes the `size-adjust` that matches Hind Siliguri's x-height to Inter's — so mixed bn/en strings sit on one baseline. The computed number is written into the CSS with the derivation in a comment. If the fetch can't run, the block ships with `size-adjust: 100%`, a TODO and a follow-up, and I say so in the report rather than pretending it's tuned.

## Risks

1. **Docker is absent (gate G0 is not clear).** No Docker, WSL2, Hyper-V or podman on this machine. Acceptance check 1's `compose up` step and anything needing Postgres cannot run. Mitigation: write the compose file correctly, validate it as YAML and against the Compose schema, and report the container step as **BLOCKED** rather than PASS. Check 2 (`pnpm dev`) is unaffected — M00's server touches no database. **M01 cannot start until this is fixed.**
2. **`actionlint` is a Go binary.** If I can't obtain it, check 4 gets a documented substitute (schema validation of the workflow) and is reported as such, not claimed.
3. **Version churn.** Every version above was read from the registry today, but a fresh `pnpm i` resolves transitive deps that may conflict. Pinning exactly plus a committed lockfile contains it; anything that has to move gets called out in the report.
4. **Tailwind 4 + shadcn.** M00 only ships the preset, no components, so an incompatibility surfaces at M05 rather than here. I'll verify the preset compiles against Tailwind 4.3.3 as part of check 5.
