## Changed on 2026-10-05 (D-561)

The owner decided to start fresh: **no** products, stock, orders, order history, offers or
settings are imported from the old website. The new website starts empty. The importer below shrinks to an **optional** customers-only import, run only if the owner chooses
(website accounts with their existing password hashes, linked to buyers by phone), so they can
sign in to the new website. Staff re-upload products and stock in the ERP (M38a). The converted
website runs first at `demo.elysium-lifestyle.bd` against Elysium's ERP at
`erp.elysium-lifestyle.bd` (D-581); the live site is untouched until the owner switches.
Where the text below still lists other kinds, they are dropped.

## What this is, in plain words

The website keeps its look, its addresses and its shopper features, but it stops having a
database and an admin panel of its own. Every page reads from the brand's ERP, and every order,
sign-up and payment goes into the ERP. `/admin` sends staff to the ERP. The products,
customers, orders, offers and settings already in the old site's database are copied into the
ERP once, checked, and the old database is switched off.

## Scope

### Website (`D:\Projects\elysium`, branch `erp-storefront`)

1. `lib/erp.js`: a server-only client for `/storefront/v1/*` (signs every request with the site
   key from env, `ERP_API_URL`, `ERP_SITE_KEY_ID`, `ERP_SITE_SECRET`), with a short cache for
   reads and typed errors.
2. Every storefront page and public route reads through it: home, shop, product, flash sales,
   cart, checkout (district and thana pickers; the server quote; idempotent placement),
   order confirmation (order view token), account (profile, addresses, orders), sign-in,
   register, email code, forgotten and reset password, about, privacy, terms, returns,
   landing pages, campaign links, tracking events, SSLCommerz return pages.
3. next-auth stays for shoppers: the credentials provider and the Google callback call the
   ERP; staff no longer sign in here.
4. Deleted: the admin panel (`app/(admin)`, `app/(admin-auth)`, `app/api/admin/*`, admin
   components), the Mongo models and `lib` code that only they used, `mongoose`, the demo kit
   (it wraps Mongo; the demo mode goes with the database — noted for the owner), `/api/ncom/*`
   (nginx sends it to the ERP), `/api/webhooks/steadfast` (couriers talk to the ERP), the
   scanner endpoints. `/admin` and `/admin/*` redirect to the ERP's admin host.
5. Kept as they are: the first-party pixel proxy paths in nginx, the CSP, the security
   headers, the image optimiser (pointed at the ERP's public media path and the CDN).
6. The scanner app's API base points at the ERP (a new APK build).

### ERP: the old site's importer (`pnpm migration legacy-site …`, D-560)

Reads a `mongoexport` of each collection (JSON files, so the ERP never connects to Mongo) and
imports through the real services, all-or-nothing per kind, with a dry run and a report like
M14a's:

| Old                                                                                                 | New                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Category (tree, codes, images)                                                                      | catalog categories with web fields                                                                                                                                                                |
| Settings.masterSizes                                                                                | the SIZE attribute's values                                                                                                                                                                       |
| Product + variants (size, price, SKU)                                                               | products and SKUs with web fields; old ids in `legacy_ids`                                                                                                                                        |
| Variant stock                                                                                       | opening stock at the web location **at the cost per piece the accountant fills in** on the exported sheet (the old site has no cost price; nothing is guessed)                                    |
| SizeChart, hero slides, menu, site info, social, announcement, promo banner, testimonials, shipping | storefront settings and tables                                                                                                                                                                    |
| Discount, FlashSale, LandingPage, CustomUrl, TrackingConfig                                         | the M35 tables (sale counters reset)                                                                                                                                                              |
| Customers (User role customer, and guests)                                                          | buyers (by phone) and website accounts (by email, with their bcrypt hashes, which stay valid)                                                                                                     |
| Orders still open (pending, processing, shipped)                                                    | real ERP orders, with stock held and, for shipped ones, the courier consignment and COD receivable through M14a's `courier_cod` import                                                            |
| Orders that are finished (delivered, returned, cancelled)                                           | a read-only order history per customer (`storefront.legacy_orders`), shown in the account and on the buyer profile; **not** posted to the books (the opening balances already carry their effect) |
| Staff users                                                                                         | not imported: staff are invited to the ERP                                                                                                                                                        |
| Images on the CDN                                                                                   | re-uploaded into ERP files (public), de-duplicated by hash                                                                                                                                        |

### Not moved

- The fraud-check accounts (see M35's owner question), notification routing (the ERP's own
  notifications replace it), CourierSyncRun, NcomEvent, NcomOutbox history, TrackingEvent logs.

## Acceptance checks

1. The importer's dry run on a copy of the live database reports every record it would create
   and every problem; the commit creates exactly that, or nothing.
2. After the import: product, SKU, customer and open-order counts match the old database; each
   SKU's stock equals the old variant stock; every old product URL and variant id resolves.
3. The website, run against a preview brand ERP, passes a Playwright run of: browse, search,
   product page, add to cart, checkout COD, checkout SSLCommerz (sandbox), sign up, verify,
   sign in, reset password, account orders, a landing-page order, a campaign link, and `/admin`
   redirecting to the ERP.
4. The website has no database connection and no admin route left (`grep` check).
5. `pnpm verify` green in the ERP; `next build` and lint green in the website.
