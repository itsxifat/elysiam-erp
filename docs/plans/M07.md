## Scope

Every unit of stock is traceable to a movement, and `stock_levels` cannot go
negative however many orders arrive at once. This milestone owns the movement
ledger, levels, reservations, weighted average cost (WAC), adjustments, two-step
transfers, count sessions and the nightly reconciliation.

## Out of scope

- Purchase receipts and supplier returns. M09 calls this module's movement API.
- Order reservation on confirm. M10 calls the reservation API built here.
- Showroom sales. M23 calls it through a POS stock port.

## Data model

Schema `inventory`, migrations 0031 to 0034.

- `stock_movements`: append-only. INSERT and SELECT only for `erp_app`.
- `stock_levels`: `on_hand` and `reserved`, with CHECK constraints that refuse a
  negative value or a reservation above what is on hand.
- `sku_costs`: the running WAC per SKU.
- `reservations`, `stock_transfers` and lines, `count_sessions` and lines,
  `adjustments` and lines, `reconciliations`.
- 0034 adds branch scope to approvals so a write-off can be held for a branch.
- Every table has `org_id`, RLS ENABLE and FORCE, and composite tenant foreign keys.

## Domain functions and what tests them

In `packages/domain/src/inventory`:

- `levels.ts` and `movements.ts`: a level is the sum of its movements. Property
  test: random sequences never leave `on_hand` negative.
- `wac.ts`: the §8 worked example reproduces to the exact poisha.
- Posting rules `stock-adjustment.ts` and the inventory lines of
  `supply-received.ts` and `supplier-return.ts`.

Reservation is one atomic conditional UPDATE in the repository, never a read
followed by a write (invariant 3).

## API, events and screens

- 19 routes under `/v1/inventory`: locations, stock, movements, valuation,
  adjustments, transfers, counts, reconciliations, reorder levels.
- `inventory.api.ts` is the service interface other modules use.
- Events: `stock.low`, `stock.drift_detected`.
- Jobs: `inventory.reconcile_levels` (nightly fan-out) and
  `inventory.reconcile_org`. Registered in `apps/server/src/job-queues.ts`.
- Console: `/stock`, `/stock/adjustments`, `/stock/transfers`, `/stock/counts`.

## Decisions

D-142 to D-147. The ones a reader should know: an opening balance is a receipt
for costing (D-142), a transfer shortfall is written off from the in-transit
location through an approval (D-143), and the drift event carries counts only
(D-144).

## Risks that mattered

- **Overselling under concurrency.** Answered by the conditional UPDATE and
  proved with 50 parallel reservations against real Postgres.
- **A vacuous property test.** The suite has a second test proving the property
  actually exercised the stock path.
- **A reconciliation job nobody runs.** The first audit found no handler in the
  worker. It is now registered, and a test drives it through real pg-boss.
