# M05: Console shell and UI kit

Phase 0 · Effort XHIGH · Depends on: M02b, M04 · Architecture §24

## Scope

The frame every later screen plugs into: the Vite/React/TanStack console, the
`packages/ui` kit, and the design system from §24 realized on M00's tokens.

Ten acceptance checks, and six of them are about _quality being verifiable_
rather than about features existing — contrast, keyboard reach, theme parity,
typography, bundle size, and a screenshot set for a human to judge. That ratio
is the milestone's real shape: the client asked for "modern, premium, clean and
professional", which is not testable by assertion, so §24 turns it into things
that are.

## What will go wrong if we are not careful

- **shadcn at library defaults.** §24 and D-033 say every colour, radius, shadow
  and duration comes from the tokens. Dropping shadcn in unmodified gives a
  competent generic app, which is exactly what the client did not ask for. The
  components get re-tuned to the tokens, and check 8 enforces it by asserting no
  component resolves a colour outside the token set.
- **Navigation driven by anything but CASL.** A sidebar built from a hardcoded
  list drifts from the matrix the moment a permission changes, and the drift is
  invisible — a link that 403s. It reads the same `defineAbilityFor` the server
  uses, and check 1 drives it as three different roles.
- **Filters in component state.** Check 2 wants them in the URL and surviving a
  reload, because an order desk shares links.
- **Money rendered by `toLocaleString`.** Invariant 1 and §24: money is always
  `<Money>`, integer poisha in, tabular numerals out, ৳ with lakh/crore
  grouping. `formatMoney` already exists in `packages/i18n`.
- **Bangla and English on different baselines.** Check 9. M00 vendored the fonts
  and computed a `size-adjust`; the kit has to actually apply it, and a mixed
  string is the test.

## Out of scope

Every module's own screens. This is the frame, a DataTable demo, the
notifications shell and the approvals inbox — the last one because it is the
first real screen and it proves the frame carries a permission-gated, realtime,
money-bearing page end to end.

## Assumptions to record

- The bundle-size target (≤250 KB gzipped for the initial route) is a budget, not
  a hard gate; if it is missed the number goes in the progress entry with what
  is in it, rather than being quietly dropped.

Built and integrated on branch `m05-console-shell`. The shell, the UI kit, the
notifications shell and the approvals inbox work, and were walked through in
Chrome as four roles.

against the real stack M11 built (`pnpm --filter @elysium/console e2e:stack`):

What the checks found and what was fixed: Bangla now loads on demand, so the
first page no longer ships both languages; the login screen and org switcher now
follow the chosen language; the two-factor enrolment screen no longer races two
secrets; the order desk's shortcut hints meet AA contrast; the Accounts link
opens the accounts screen instead of a placeholder; and Better Auth's sign-in
limit no longer locks out the sixth person on a shared office address (D-168).

**For a person to judge:** the screenshot set. Automated checks cannot say
whether the console looks premium.

Follow-ups: a UI-kit date field to replace the native date input. The acceptance
audit for M05 is still owed.
